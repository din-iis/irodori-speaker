# BGM ステップ（`bgm`）実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 合成済みの朗読（章 WAV）に、Freesound から自動で選んだ環境音と音楽を重ね、章ごとと通しの MP3 を書き出す `bgm` サブコマンドを作る。

**Architecture:** `bgm` は `synth` の後に走る独立した工程で、`script.tsv` / `chapters.json` / 章 WAV と `.times.json` だけを読む。LLM で場面を区切り、Freesound を検索し、LLM で候補をふるい分けてから LLM を解放し、CLAP で順位を付けて選ぶ。最後に numpy で時間の並びを組んで重ね、ffmpeg で MP3 にする。各段の結果は本ごとのキャッシュに残し、再実行で続きから進む。

**Tech Stack:** Python 3.10、numpy、soundfile、requests、ffmpeg（デコード・リサンプリング・MP3 書き出し）、transformers + torch（CLAP、遅延 import）、pytest。

**Spec:** `docs/superpowers/specs/2026-10-31-bgm-design.md`（各タスクの実装者は計画と一緒に必ず読む）

## Global Constraints

- 返答・コメント・ユーザー向けメッセージは日本語（既存コードと同じ）。
- Mac には torch / GPU が無い。torch と transformers は `bgm_select.ClapScorer` の中でだけ import する。他の bgm モジュールのトップレベルで import しない。
- Freesound の API キーは `~/.config/irodori-speaker/secrets.env` の `FREESOUND_API_KEY=` 行にだけある。実装・テストのどちらもこの実ファイルを読まない（テストは `tmp_path` に偽のファイルを作る）。キーは `Authorization: Token <key>` ヘッダーで API ホスト（`https://freesound.org/apiv2`）にだけ送り、URL・例外メッセージ・ログ・キャッシュに含めない。試聴用 MP3 の取得にはキーを付けない。
- 8GB GPU に LLM と CLAP を同時に載せない。LLM の処理（場面・ふるい分け）を全部済ませて `unload` してから CLAP を作る。
- LLM の呼び出しは既存の `llm` 設定（Ollama ネイティブ `/api/chat` / openai 互換）をそのまま使う。
- MP3 は ffmpeg で書く。ffmpeg が無いテストは `pytest.mark.skipif` で飛ばす。
- 書き出しは一時ファイル経由で置き換える（既存の `assemble.py` と同じ）。
- 既存のテスト（`uv run pytest -q`）を壊さない。
- 依存の追加は `pyproject.toml` の extra `bgm = ["transformers"]` だけ。librosa は使わない。

## Review Focus

1. 章全体が `min_scene_chars` より短い、または場面が 1 つしかない章 → 1 場面になり、bridge は 0 個。章頭の intro だけが付く（Task 2・Task 5 のテストに含める）。
2. 環境音の素材がループのクロスフェード（2 秒）の 2 倍より短い（例: 3 秒） → 例外を出さずにループする（Task 5）。
3. Freesound の説明文に改行・タブ・数千文字が入っている → ふるい分けのプロンプトは 1 候補 1 行、`gate.tsv` の行が壊れない（Task 4）。
4. 1 日の上限で止まった後の再実行 → キャッシュ済みの検索語では API を呼ばない（Task 4 のテストで偽クライアントの呼び出し回数を数える）。
5. 環境音が無い場面（`ambient_query` が `null` か見つからない）と bridge が隣り合う → 存在しない環境音にフェードを付けず、時間の並びが崩れない（Task 5）。

```python
@dataclass
class Scene:
    chapter: int                # 0 始まり
    index: int                  # 章内の場面番号（0 始まり）
    start_para: int
    end_para: int               # この場面の最後の段落（含む）
    description: str            # 英語の場面説明
    ambient_query: str | None   # None は意図した無音
    mood: str
    music_query: str            # 空文字は音楽を探さない
    status: str = "ok"          # "ok" | "llm_error"

@dataclass
class Sound:
    id: int
    name: str
    tags: list[str]
    description: str
    duration: float
    license: str                # Freesound の license URL
    username: str
    url: str                    # Freesound のページ
    preview: str                # preview-hq-mp3 の URL

@dataclass
class Choice:
    chapter: int
    scene: int
    kind: str                   # "ambient" | "intro" | "bridge"
    query: str
    sound: Sound | None
    score: float | None
    reason: str | None          # None は選べた。"no_result" | "all_rejected" | "llm_error" | "error"
```

`Scene` / `Sound` / `Choice` には `to_dict()` と `from_dict(d)`（classmethod）を付ける（JSON の保存用、`Choice.sound` は入れ子の dict）。

```
場面 k の朗読区間（元の WAV 上）:
  開始 = 0（k=0）/ 前の場面の最後の段落の end
  終了 = この場面の最後の段落の end（最後の場面だけ frames）
t = 0
intro があれば: music[intro] = [0, I)、fade_in=fi, fade_out=fo。t = I
場面 0 の環境音の開始 = intro があれば I - fo、無ければ 0。fade_in = intro があれば fo、無ければ X
各場面 k について:
  voice に (元の開始, 元の終了, t) を足し、t += 区間の長さ
  k が最後でなければ境界 b = t:
    bridge（場面 k+1 の音楽）があれば:
      music[bridge] = [b, b+B)、fade_in=fi, fade_out=fo
      場面 k の環境音は b+X で終わる（fade_out=X）
      場面 k+1 の環境音は b+B-fo から始まる（fade_in=fo）
      t = b + B
    無ければ:
      場面 k の環境音は b+X/2 で終わる（fade_out=X）
      場面 k+1 の環境音は b-X/2 から始まる（fade_in=X）
最後の場面の環境音は t+T で終わる（fade_out=T）。環境音のある場面が最後なら total = t+T、無ければ total = t
環境音の無い場面（ambient_query None または選べていない）には Track を作らない。隣の場面の Track は上の規則のまま
```

  - フェードは線形。Track の音は `trim_silence` → `loop_to(長さ end-start)` → 音量 → フェードの順に作る。
